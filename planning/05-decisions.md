# ColorSense 결정 기록 (Mateus)

작성: 2026-09-14 · 이 문서는 팀이 참조하는 확정 결정의 단일 출처다. 변경 시 날짜와 사유를 아래에 덧붙인다.

## 확정 결정

### D1. 1차 런칭 범위와 데이터 소스
- 1차 런칭 = 한국 주요 도시(기상청 예보 제공 범위) + 해외 소수 국가 주요 도시(Open-Meteo 무료 티어).
- 데이터 소스는 무료 범위로 제한: 기상청(공공데이터포털/API허브), 한국환경공단 에어코리아, 한국천문연구원 출몰시각, Open-Meteo 무료 티어.
- 클라이언트는 외부 API를 직접 호출하지 않는다. BFF가 수집·캐시·정규화하고 클라이언트는 BFF 계약(`backend/api-contract.md`)만 본다.

### D2. 스토어 공개 여부 (최종 결정 1)
- **1차는 비공개 배포**: iOS TestFlight 내부 테스트, Android 내부 테스트 트랙, 웹은 접근 제한 URL.
- 사유: Open-Meteo 무료 티어의 비상업 조건을 가장 안전하게 지키는 배포 형태이고, QA 대상 기기·OS 범위를 팀 보유 기기로 한정할 수 있다.
- 스토어 공개(2차)는 데이터 소스 계약(Open-Meteo Standard 등) 재검토와 동시에 결정한다. 앱은 광고·유료 기능을 갖지 않는다.

### D3. 날씨 라벨 용어 (최종 결정 2)
- **기상청 용어 우선**. 공통 모델 `sky` 단계별 한국어 라벨: 0 맑음 · 1 구름조금 · 2 구름많음 · 3 흐림. 영어는 CLEAR · MOSTLY CLEAR · PARTLY CLOUDY · CLOUDY 유지.
- 강수: 비 · 이슬비 · 눈 · 진눈깨비(비/눈), 소나기는 "구름많음 & 비"가 아니라 라벨 "소나기"를 별도 사용. 강도 접두어 "약한/강한" 유지.
- 사유: 한국 도시가 1차 중심이고, 사용자가 기상청 예보와 앱을 비교했을 때 용어가 같아야 "정확하다"고 느낀다.

### D4. 계절 틴트 및 스테일 표현 (최종 결정 3)
- **계절 틴트 제거**. 배경색은 온도 대역 + 날씨 구성 + 주야만으로 결정한다. 컬러 테스트의 계절 칩도 제거한다.
- 사유: 해외 도시(열대·남반구)에서 월 기반 계절이 어색하고, 웹·앱 간 색 일치를 위해 입력 변수를 줄이는 편이 안전하다. 계절감은 온도 팔레트가 이미 담고 있다.
- **스테일·대체·지연·오프라인 상태는 배지로만 표현**하고 배경색은 건드리지 않는다. 배경색 = 날씨라는 약속을 데이터 상태로 오염시키지 않는다.

### D5. 즐겨찾기 상한 및 갱신
- 즐겨찾기 도시 상한 10개. 현재 위치 1개는 별도.
- 한국 도시는 기상청 발표 시각 기준 스케줄 수집, 해외 도시는 최근 24시간 내 조회된 도시만 30분 주기 수요 기반 갱신.
- 클라이언트는 `nextUpdateAt` 이전에는 재요청하지 않는다. 스테일 기준: `updatedAt` + 3시간.

### D6. 1차 데이터 항목
- 필수: 현재 온도, 체감온도, 날씨 구성(공통 모델), 시간별 24시간(온도·강수확률·구성), 일별 7일(최고/최저·구성), 습도, 풍속·풍향, 강수확률, 일출·일몰, 미세먼지/황사 등급.
- 2차: 파도, 자외선, 기상특보 푸시, 홈 위젯.
- 해외 도시 대기질은 모델 예측값이므로 "예측" 표기.

### D7. 앱 구현 방식
- **네이티브 두 벌(SwiftUI · Jetpack Compose)**. Flutter/React Native 미채택.
- 사유: 앱의 핵심이 배경 그라데이션·블러·파티클이라 플랫폼 렌더러를 직접 쓰는 편이 품질·배터리에 유리하고, 화면 4장 규모라 유지 비용이 작다. 컬러 엔진은 언어별 이식 + `frontend/spec/color-engine.json` 골든 테스트로 ±1 일치를 강제한다.
- 위치 권한은 "사용 중"·대략적 위치만 요청. 상세는 `app/README.md`.

### D8. 날씨별 음향·햅틱 (F-18·F-19, P-11)
- 환경음: 날씨 구성에 맞는 앰비언트 루프(기저 레이어 + 강수 레이어) + 뇌우 원샷. **기본 꺼짐**, 홈 표시 중에만, 색 전환과 같은 1.2s 크로스페이드. 무음 스위치·다른 앱 오디오·백그라운드 존중.
- 햅틱: 도시 전환·시트 열림/닫힘·천둥 번쩍임·강수 강도 변화 이벤트에만. **기본 켜짐**, 시스템 햅틱 설정·저전력 존중. 상시 진동 없음.
- 음향·햅틱은 정보의 유일한 통로가 될 수 없다(항상 색·라벨과 중복). 매핑표는 `planning/06-planning-and-screen-spec.html` §8, `design/sound-and-haptics.md`.

### D9. 기술 스택
- 웹 React 18 + Vite + TS(점진) · iOS Swift/SwiftUI + AVFoundation + Core Haptics · Android Kotlin/Compose + Media3 + VibrationEffect · BFF Node 22 + TypeScript + Hono + Zod · DynamoDB 단일 테이블 + S3 카탈로그 · AWS CDK(TS) · GitHub Actions · Sentry 무료.
- 공유 패키지 `packages/core`(model·kma·color)를 웹과 BFF가 함께 import. 상세와 제외 사유는 `planning/07-tech-stack.md`.

- D10-1 **하단 도크 도입, 좌표 문자열 유지**: 도크 왼쪽 위치 칩 = 출처 아이콘(◎ GPS · ⌂ 기본 · ★ 즐겨찾기) + 라벨 + 좌표 "KST · 35.18, 129.08"(모노스페이스, AX 큰 글씨에서 먼저 숨김), 탭 → 도시 선택. 오른쪽 ⌃ → 상세 시트. 도시명·국가는 콘텐츠 층에 그대로. P-09 유지.
